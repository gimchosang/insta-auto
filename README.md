# insta-auto

인스타그램 다계정 자동 발행 파이프라인. **서버 없이 GitHub 안에서만 돌아가고, 비용이 들지 않습니다.**

```
매시 정각 (GitHub Actions)
   ↓  지금 발행할 계정이 있나?
소재 확보          유머 → AI 생성 / 지역 → 서울시 공공데이터
   ↓
문구 생성          Gemini 무료 티어, 1장 후킹 + 3~4장 전개
   ↓
카드 렌더링        HTML 템플릿 → 1080×1080 JPEG 여러 장
   ↓
GitHub Pages       이미지 공개 URL 확보 (인스타 API 요구사항)
   ↓
Instagram API      캐러셀 컨테이너로 묶어 발행
```

## 카드 구조

```
1장 (hook)   손가락을 멈추게 하는 문구. 각 줄 9자 이내, 2~3줄.
             계정별 고유 색 조합 + 디스플레이 폰트 + 흰 테두리.
2~5장 (body) 후킹이 약속한 내용을 실제로 푸는 부분.
             한 장에 한 가지 이야기. 진행 표시용 번호와 점.
```

문구는 한 덩어리가 아니라 **줄 배열**로 생성됩니다. 썸네일에서 줄바꿈 위치가 곧 리듬이고, 자동 줄바꿈에 맡기면 이 리듬이 죽기 때문입니다.

| 템플릿 | 쓰임 |
|---|---|
| `punch` | 유머 계정 1장 — 텍스트만 화면 가득 |
| `local-punch` | 지역 계정 1장 — 카테고리 + 후킹 + 핵심 정보 |
| `body` | 모든 계정 2장부터 공통 |

계정의 정체성은 `style` 의 색 4개(`bg` `fg` `stroke` `hit`)와 `font` 가 만듭니다. 계정을 늘릴 때 새 색 조합만 정하면 됩니다.

## 왜 이 구조인가

| 선택 | 이유 |
|---|---|
| 공식 Content Publishing API | 비공식 자동화(Selenium·instagrapi)는 약관 위반이라 계정이 정지됩니다 |
| AI 이미지 생성 대신 HTML 템플릿 | 무료이고, 품질이 일정하고, 계정별 브랜드 톤을 고정할 수 있습니다 |
| 지역 소재는 공공데이터만 | 공공저작물이라 저작권이 깨끗합니다. 소재가 없으면 **지어내지 않고 건너뜁니다** |
| GitHub Actions | 서버·결제수단이 필요 없고, 퍼블릭 레포는 실행 시간이 무제한입니다 |

## 지금 설정된 계정

| 계정 | 성격 | 발행 시각(KST) | 색 조합 | 소재 |
|---|---|---|---|---|
| `univ-humor` | 대학생 공감 | 23:00 | 민트 × 핑크 | AI 생성 |
| `office-humor` | 직장인 공감 | 08:00 | 노랑 × 검정 | AI 생성 |

| `seongbuk-campus` | 성북 대학가 정보 | 18:00 | 파랑 × 노랑 | 서울시 문화행사 API |

## 처음 시작하기

**[docs/SETUP.md](docs/SETUP.md) 를 순서대로 따라가세요.** 순서가 중요합니다.

요약하면:

1. 레포를 GitHub 에 올리고 **Pages 를 켭니다** (Settings → Pages → main 브랜치 `/docs`)
2. **미리보기부터 돌려봅니다** — 인스타 계정 없이도 카드가 어떻게 나오는지 볼 수 있습니다
3. 인스타 계정을 만들고 **프로페셔널로 전환**한 뒤 일주일 워밍업
4. Meta 개발자 콘솔에서 **토큰 발급** (가장 오래 걸리는 단계)
5. 시크릿을 넣고 `enabled: true` 로 바꾸면 가동

## 미리보기 (계정 없이 실행 가능)

`GEMINI_API_KEY` 하나만 있으면 됩니다.

**Actions 탭 → "미리보기" → Run workflow**

계정과 생성 개수를 고르면, 실행이 끝난 뒤 페이지 맨 아래 **Artifacts** 에서 카드 이미지를 내려받을 수 있습니다. 생성된 문구는 실행 요약에 바로 표시됩니다. 발행은 일어나지 않습니다.

### IG_ACCOUNTS 형식

계정마다 시크릿을 2개씩 만들지 않고, JSON 하나에 모읍니다:

```json
{
  "univ-humor":      { "token": "IGAA...", "userId": "17841400000000000" },
  "office-humor":    { "token": "IGAA...", "userId": "17841400000000001" },
  "solo-life":       { "token": "IGAA...", "userId": "17841400000000002" },
  "seongbuk-campus": { "token": "IGAA...", "userId": "17841400000000003" }
}
```

키는 `accounts/*.json` 의 `id` 와 정확히 같아야 합니다.

> **왜 이렇게 하냐면** — 워크플로에 `toJSON(secrets)` 로 시크릿 전체를 넘기면 계정 추가가 편하지만, 그 잡에서 도는 모든 코드(npm 의존성 포함)가 모든 시크릿을 읽을 수 있게 됩니다. GitHub 도 이 패턴을 위험으로 차단합니다. 계정 자격증명만 한 곳에 모으면 워크플로는 계속 고정이면서 노출 범위가 줄어듭니다.

## 계정 추가하기

`accounts/_TEMPLATE.json` 을 복사해서 새 파일을 만들고, `IG_ACCOUNTS` 에 항목 하나를 추가하면 끝입니다. **코드도 워크플로도 건드리지 않습니다.**

지역 계정은 `source.region` 만 바꾸면 다른 구로 그대로 복제됩니다:

```
안암  →  회기 (경희대·외대·시립대)   source.region.gu = "동대문구"
      →  정릉 (국민대·서경대)
      →  신촌 (연대·서강·이대)        source.region.gu = "서대문구"
```

유머 계정은 `persona` 의 `who` / `voice` / `topics` 만 교체합니다.

> **한 번에 여러 개 만들지 마세요.** 계정을 짧은 기간에 대량 생성하는 것 자체가 인스타의 탐지 대상입니다. 주당 2~3개씩 늘리고, 새 계정은 `enabled: false` 로 두었다가 워밍업이 끝나면 켜세요.

## 필요한 시크릿

**Settings → Secrets and variables → Actions**

| 종류 | 이름 | 용도 |
|---|---|---|
| Secret | `GEMINI_API_KEY` | 문구 생성 ([무료 발급](https://aistudio.google.com/apikey)) |
| Secret | `SEOUL_API_KEY` | 지역 계정 소재 ([무료 발급](https://data.seoul.go.kr/together/mypage/actKeyList.do)) |
| Secret | `IG_ACCOUNTS` | 계정별 토큰·ID를 담은 JSON **하나** (아래 참고) |
| Secret | `GH_PAT` | 토큰 자동 갱신용 (없으면 갱신을 수동으로) |
| Variable | `PAGES_BASE_URL` | 예: `https://아이디.github.io/insta-auto` |

## 워크플로

| 이름 | 언제 | 하는 일 |
|---|---|---|
| 매일 발행 | 매시 정각 | 해당 시각의 계정만 발행. 없으면 즉시 종료 |
| 미리보기 | 수동 | 카드 생성만. 발행 안 함 |
| 토큰 갱신 | 매월 1일·15일 | 60일 만료 토큰을 자동 갱신 |

발행이 실패하면 자동으로 이슈가 생성됩니다.

## 알아둘 것

- **발행 시각은 정확하지 않습니다.** GitHub Actions 크론은 부하에 따라 수 분~수십 분 밀립니다. 여기에 `jitterMinutes` 랜덤 대기가 더해집니다.
- **인스타 발행 한도는 계정당 24시간 100건**입니다. 캐러셀은 몇 장이든 1건으로 셉니다.
- **같은 날 두 번 발행되지 않습니다.** `state/published.json` 에 기록이 남습니다.
- **지역 계정은 새 소재가 없으면 그날을 건너뜁니다.** 없는 행사를 지어내는 것보다 낫습니다.
